# Cleanup and performance, 13 October 2026

The tracked project contains 164 files before this patch. Source imports, data consumers, media references, release scripts and deployment configuration were inspected. TypeScript's no-unused-locals/no-unused-parameters check identified an unused Link import and unused URL helper in Salon.tsx; both were removed. The superseded bridal-makeup-stock.webp and its matching CSS selector were removed from deployment, with source attribution retained in the private asset-credit history. Git can recover the removed artwork. Original supplied assets, current film/photo variants, third-party licences, copyright, Google verification, migration scripts and release evidence remain necessary and were preserved.

Do not treat every small thumbnail as a duplicate: service thumbnails and complete photos serve different layouts. Do not delete uploaded images or products merely because a record is a draft. Draft deletion is an explicit authenticated action with confirmation and a server-side status guard; published products are protected from that operation.

Observed production response samples before the change: /fr first byte 3.24 seconds, /fr/produits 2.10 seconds (single samples from this computer, including network latency). The old code fetched four database queries on every public page and always retransferred product media. Public data caching, immediate mutation invalidation, bounded image variants and conditional image responses address those causes without weakening private-data controls.

Local production samples with public catalogue caching: /fr/produits 286 ms, next request 32 ms; /fr 27 ms. These are local diagnostic results, not a promised live-site timing or a like-for-like network benchmark.

The mobile salon film is 4,120,182 bytes versus 7,934,388 bytes for the original desktop rendition (about 48% less). The complete film/aspect ratio is retained; desktop uses the original rendition. The bridal film still waits for user playback before fetching, and keeps its audio controls.

All ten application tables were transferred to Supabase and compared to a fresh source snapshot with row counts and SHA-256 checksums. Restricted-role, verified client TLS, session, CSRF, product writes, media privacy, published-product deletion rejection, draft deletion and logout checks passed. Temporary test products/categories/sessions were removed and the full comparison passed again. The old provider's runtime code/certificate and completed one-time transfer helpers were removed. A static certificate path avoids tracing unrelated project/private files into the server bundle. See SUPABASE-MIGRATION-RESULT.json for the separate deployment verification state. Older handoffs remain historical evidence.
